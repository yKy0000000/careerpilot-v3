# CareerPilot v3 — L10 最终报告（缓存布局）

> 定稿：2026-08-24
> 口径：off-peak 人民币计价，`thinking=disabled` 确定性口径（但见 §4.3，输出仍非确定）
> 三臂：workflow（固定 top-5 检索）/ agent-baseline（工具调用循环）/ full-context（KB 全灌不检索）
> 知识库指纹：`2536f4c3efc6`（2341 token）
> 样本：30 条真实 JD，三臂各 30/30 成功

---

## 一、结论先行

| 结论 | 证据 | 判定 |
|---|---|---|
| 缓存只优化输入，而输入只占账单的 5~6%（workflow/full-context） | 输入成本占比 5.4% / 5.8% | 缓存在这个负载下不值钱 |
| 命中率是虚荣指标 | agent hit 占量 63%、占钱 5.4% | 命中率 ≠ 省钱率 |
| 多轮 agent 靠缓存变便宜是错觉 | 成本比 4.06x，`N > H/30` 超出 13.7 倍 | 缓存省不掉「新增」 |
| `temperature` 参数始终无效 | 三臂两遍 0/30 逐字一致 | 无法通过参数拿确定性 |
| 架构最优解：固定检索 | 质量三臂打平，成本 workflow < full-context < agent | workflow 净正、agent 净负 |

**四句话：**

1. **reasoning token 是与架构无关的共同项**——它占 enabled 时输出的 80%+，把 agent/full-context 的成本比从真实的 4.06x 压成假的 1.41x，与 L9 的 gaps 池化 bug 是同一种「共同项污染比值」。
2. **缓存只省「重复」、不省「新增」**——agent 多轮循环每轮新增的工具结果 + assistant 调用永远是 miss，命中率 84% 是「轮内」（架构自带），但命中的 token 占钱仅 5.4%。
3. **`deepseek-v4-flash` 的 `temperature` 参数被静默忽略**（thinking 开关都不影响），输出本质随机——所有单次跑的数字都是带噪声的样本，判断差异必须用配对检验。
4. **架构结论：固定前置检索（单次调用）是这个负载下的最优解**，工具调用（多轮循环）纯负收益。

## 二、L10 在测什么

L9 结论「检索净负收益」：agent 成本是 full-context 的 2.5x（total_tokens 口径），且三臂 gaps recall 无显著差异。

L10 的唯一动机：**agent 多轮循环理论上最受益于自动前缀缓存（每轮复用历史前缀），「检索净负收益」会不会被缓存改写？**

价目（off-peak，元/百万 tokens）：输入命中 0.05 / 未命中 1.5 / 输出 4.5，命中折扣 1/30。

## 三、成本结构（thinking=disabled，30 条总和）

## 四、三大发现

### 4.1 reasoning token 是「共同项」，污染了成本比

enabled → disabled 的 output 对比：workflow 112094→17337（-84%）、full-context 145736→20715（-86%）、agent 162358→40198（-75%）。

enabled 时 output 里 80%+ 是 reasoning token（思考过程，按 4.5 元/百万计价）。它是**与架构选型无关的巨额共同项**，同时抬高三臂的分子分母，把比值机械地压向 1：

| 口径 | agent / full-context 成本比 | 相对上一行变了什么 |
|---|---|---|
| L9 无缓存 · enabled | 2.5x | — |
| L10 缓存 · enabled | 1.41x | 只加了缓存（收窄，假设成立） |
| L10 缓存 · disabled | **4.06x** | 又关了 thinking（移除共同项，反转） |

**开缓存确实收窄了成本差（2.5x→1.41x），但收窄是假性的**——reasoning 共同项把比值压向 1；移除后架构真实成本差是 4.06x。

### 4.2 缓存只省重复、不省新增

agent 逐轮 hit/miss（30 条累加，run2）：

| 轮 | hit | miss | 该轮命中率 |
|---|---|---|---|
| 1 | 33408 | 1668 | 0.952 |
| 2 | 64000 | **88050** | **0.421** |
| 3 | 63872 | 23466 | 0.731 |
| 4 | 29568 | 6570 | 0.818 |
| 5 | 20736 | 3246 | 0.865 |

轮内 vs 轮间拆分：**轮间命中（turn1，跨请求）占 15.8%，轮内命中（turn2+，复用前一轮）占 84.2%**。agent 的高命中率绝大部分是「架构自带红利」（复用自己前一轮），不是排布挣的。

**成本大头是「新增 miss」，集中在 turn2**：turn2 的 miss 88050 占全部 miss 的 71.6%——第一轮工具调用塞进来的检索结果（8.8 万 token）是缓存的结构性盲区。

**可迁移规则 `N > H/30`**：每加一轮，成本增量 = `0.05×历史长度(hit) + 1.5×新增长度(miss)`。miss 主导的条件是 `N > H/30`。实测 agent 单条：H/30=334，N=4578，**超出 13.7 倍**。多轮 agent 靠前缀缓存变便宜是错觉——新增内容随轮数线性增长，是缓存救不回来的。

### 4.3 temperature 参数始终无效，输出本质随机

`--tag run1/run2` 连跑两遍 diff `model_result`：**三臂全部 0/30 逐字一致**，每条 JD 有 5~26 处差异（evidence 措辞 → severity 翻档 → gaps 数量变化）。

这不是浮点抖动（那只会是稀疏平局翻转），而是服务端在做真实随机采样——`temperature=0` 被静默忽略，`thinking` 开关都不影响。

**后果**：所有单次跑的数字都是带噪声的样本。判断「两臂差异」不能看均值差，必须配对检验。这解释了 L9 的「11/30 match_score 翻转」「seed=42 无效」，且证明该随机性不是 thinking 的锅，是模型的固有属性。

## 五、架构结论（质量 + 成本综合）

### 质量：三臂 gaps recall 无统计差异

配对 Wilcoxon（workflow vs full-context，逐 JD recall）：

| | run2 | run1 |
|---|---|---|
| workflow 宏平均 recall | 0.646 | 0.655 |
| full-context 宏平均 recall | 0.648 | 0.650 |
| 优/劣/平 | 5/5/20 | 5/5/20 |
| p 值 | 0.6089 | 0.9188 |

两次 p 均 ≫ 0.05，20/30 条 recall 完全打平。L9 的「workflow 未参与成本对比」被补齐后，workflow 与 full-context 的 gaps 判断不可分辨——**判断「缺什么」主要靠 JD 文本本身，检索/全灌在「候选人有什么」上信息量等价。**

### 成本：workflow < full-context < agent

| arm | 有效成本(元) | gaps recall | 定性 |
|---|---|---|---|
| workflow（固定检索） | 0.0824 最低 | 与 full-context 无差异 | **净正** |
| full-context（全灌） | 0.0989 | 基准 | 中性 |
| agent-baseline（工具调用） | 0.4020 最贵 | 无差异 | **净负** |

**最终结论：固定前置检索（单次调用）最优，工具调用（多轮循环）纯负收益。**「检索净负收益」被拆成两半——L9 错在把 workflow 的 token 记为 `nan`，让「检索」被 agent 单独代表；正确说法是「工具调用检索净负、固定检索净正」。

## 六、方法论沉淀（两次踩坑，同一个病灶）

| 层级 | 病灶 | 后果 |
|---|---|---|
| L9 | gaps 池化：30 条 JD 并成大集合 | 分母虚大 → recall 虚高 0.94（真值 0.66~0.75） |
| L10 | reasoning token：占输出 80% 的架构无关项 | 分子分母同时虚大 → 成本比虚小 1.41x（真值 4.06x） |

**可复用检查项：任何比值型指标，先问「分子分母里有多少是与自变量无关的共同项」；共同项越大，比值越向 1 收敛，真实效应被系统性低估。**

配套铁律：命中率必须拆「轮内 vs 轮间」并带参照物；只报命中率不带有效成本 = 重蹈池化口径覆辙。

## 七、遗留与下一步

- **cache-hostile 阴性对照（第 4 步）未做**：因「命中率是虚荣指标」已定性（hit 占钱 5.4%），cache-hostile 降级为「验证测量正确性」。如补做，在 `SYSTEM_PROMPT` 首行插 `# request_id: {uuid4()}`，预期命中率→0。
- **布局审计（第 5 步）降级**：缓存剩余上限 ≤3.4%，确认已近最优即可，不追求人为制造提升。
- **质量基线**：disabled 三组（recall 0.674~0.729，evidence 0.953~0.989）为 L10 新基线；因输出随机，后续质量对比需多次跑 + 配对检验，不用 L9 enabled 基线。
- **L11 收口**：把 L9/L10 的完整结论（逐项可溯源诊断可靠、整体打分不可信、固定检索最优）合并成项目终稿。
