# eval/annotate.md —— L8 标注准则（先写完再标第一条）

## 0. 总则
- 标注对象 = 候选人本人，能力范围以 `kb/docs/`（resume + 3 个项目文档）为准，不脑补。
- 语义：`human_match_score` = 「能否胜任」，与 L2 的 `match_score` 同一语义。
- 铁律：先标注，后跑 Agent；禁止看着 Agent 输出回头改标注。
- 准则一旦改动，前面标过的全部重标，并在「准则改动记录」追加一条。

## 1. human_match_score 分段定义（5 档 × 20 分，只写档上限）
| 档 | 分值 | 判据 |
|---|---|---|
| 1 | 20 | 完全不能胜任，能力范围与岗位需求完全不匹配 |
| 2 | 40 | 不能胜任，个别硬性要求（1-2 条）符合岗位需求 |
| 3 | 60 | 能力略有欠缺，广度初步覆盖但深度不够（岗位要精通/完全掌握，候选人只熟悉/了解） |
| 4 | 80 | 大部分符合，但缺核心/差异化那一两项 |
| 5 | 100 | 高度匹配，核心能力符合且有切实经历作证据，某一方面了解深入 |

只写档上限 `20 / 40 / 60 / 80 / 100`，档内不再细分。

## 2. human_gaps 粒度
- 写**具体技术/框架**（FastAPI、PPO、LangGraph），不写能力域（Web、并发、RL）。
- JD 用斜杠/顿号列举多个等价技术时，按候选人所缺的具体项拆分：
  JD 写「PPO/DPO/GRPO」，候选人只有 DPO → gap 写 `PPO`、`GRPO` 各一条（DPO 已具备，不算 gap）。
- 每条 gap 结构固定为 `{skill, severity}`，不加其他字段。

## 3. severity 三档判据（锚 JD 措辞，与 prompts.py 一致）
- **硬性**：JD 写「必须 / 精通 / 熟练掌握 / 核心职责」的缺口
- **明显**：JD 写「熟悉 / 要求 / 具备」的缺口
- **轻微**：JD 写「了解」的缺口
- **优先 / 加分项**的缺失**不计入 gaps**（命中只记 `notes`，不跨档、不进 score）

## 3.5 职责 vs 要求
- 匹配判断锚**任职要求**；岗位职责只提供上下文（判断哪个要求是核心）。
- 岗位职责里出现的**具体技术词**同等计入；纯流程/软性描述（沉淀文档、团队分享）不计。
- 职责里的技术词**不带程度词**时，severity 按优先级：
  1. 要求里也提到 → 以要求措辞定（要求 > 职责）。
  2. 要求没提、只在职责 → 默认「硬性」（锚「核心职责 → 硬性」）。
  3. 例外：职责是「参与 A/B/C/D」枚举式能力面 → 判「是否差异化核心」：是 → 硬性，否 → 明显或不计。

## 4. 技能名归一化规则（aliases.json）
- canonical 形态：库/框架用英文名（`FastAPI` / `LangGraph` / `asyncio`）；概念用中文（`检索增强` / `函数调用`）。
- 等价规则：大小写统一（`langgraph` → `LangGraph`）；中英别名（`函数调用` = `Function Call` = `Tool Calling`）；近义（`协程` = `asyncio`）。
- `aliases.json` 结构：`{ canonical: [原子变体...] }`，变体为**原子形式**（不含顿号捆绑）。
- **归一化算法（L9 用）**：gap 技能名 → 去空白 → 对每个 canonical 的变体做**子串匹配**（含即命中）→ 返回命中的 canonical 集合。这样捆绑项（`ReAct、Plan-and-Execute`）自然拆成 `{ReAct, Plan-and-Execute}`，同义词（`Function Calling、Tool Use`）合并成 `{函数调用}`。
- 已知局限：短 token（`NLP`/`Go` 等）子串匹配偶有误命中，如「NLP 相关开发经验」会同时命中 `工作经验` + `模型训练原理`。L9 统计时可忽略该量级噪声。
- 定稿条件：跑 baseline 之前定稿；跑完发现 recall 低再补别名 = 自欺，禁止。

## 5. dataset.jsonl 字段
每行一个 JD，字段：
- `jd_id`：jd-01 ~ jd-30
- `company`：公司名
- `title`：职位名
- `jd_text`：JD 原文（对应 `eval/jds/jd-XX.md` 正文）
- `human_match_score`：整数，档上限 20/40/60/80/100
- `human_gaps`：`[{skill, severity}]`
- `real_outcome`：`未投递 / 已投递-无回复 / 已投递-约面 / 已投递-拒绝`（未投递先留空）
- `notes`：标注备注（可选）

## 6. 标注流程与纪律
1. 先标注，后跑 Agent。
2. JD 优先用真的投过的（real_outcome 是最硬 ground truth）。
3. 一致性检验：30 条分两天标（20 + 10），第二天重标第一天里的 5 条，算平均差值；> 15 分 → 修准则重标，记进 `consistency.md`。
