## 零、一句话

**数字是对的，归因是错的。**

第八节写「原假设被证伪」——但表里自带反证：加缓存这一步，成本差确实按预期从 2.5x 收窄到 1.41x；把它掀翻的是**关 thinking**，不是缓存。

真正的产出不是「缓存优化」（在这个负载上只值 3%），而是**为了测缓存而把成本拆成输入/输出，从而抓出了 reasoning token 这个混淆项，并顺带推翻了 L9 的主结论。**

## 一、原假设不是被证伪，是被混淆

| 口径 | agent / full-context 成本比 | 相对上一行变了什么 |
|---|---|---|
| L9 无缓存 · thinking=enabled | 2.5x | — |
| L10 缓存 · thinking=**enabled** | **1.41x** | **只加了缓存** |
| L10 缓存 · thinking=**disabled** | **4.06x** | **又关了 thinking** |

**第二行说明原假设（缓存收窄成本差）在自己的口径里是成立的。**

原文档把 1.41x 标注为「假象」。这个判断结果对，但**理由没写出来**，导致现在的叙事把关 thinking 的效应错记在缓存账上。

### 正确表述

> 缓存按预期收窄了成本差（2.5x → 1.41x）。但这个收窄是**假性的**——reasoning token 是一个占输出 80%+、**与架构选型完全无关**的巨额共同项，它同时抬高三臂的分子和分母，把比值机械地往 1 压。关掉 thinking 移除共同项后，架构本身的真实成本差暴露为 **4.06x**。

| | 判定 |
|---|---|
| ❌ 「原假设被证伪」 | 归因错误，且把方法论发现降级成一次猜错 |
| ✅ 「原假设在被污染的口径下**看起来成立**；移除混淆项后方向反转」 | 同一份数据，强得多 |

### ⚠️ 这是本项目第二次撞上同一个病灶

| 层级 | 病灶 | 后果 |
|---|---|---|
| L9 | gaps **池化**：30 条 JD 并成一个大集合 | 分母虚大 → recall 虚高 0.94（真值 0.66~0.75） |
| L10 | **reasoning token**：占输出 80% 的架构无关项 | 分子分母同时虚大 → 成本比虚小 1.41x（真值 4.06x） |

**共同结构：一个巨大的、与自变量无关的共同项污染了比值。**

这个模式已经出现两次，应当单独记录成一条可复用的检查项：
> **任何比值型指标，先问"分子分母里有多少是与自变量无关的共同项"。共同项越大，比值越向 1 收敛，真实效应被系统性低估。**

这比任何单条指标都更接近"能力"，值得写进项目叙事。

## 三、「缓存只省重复不省新增」的量化机制

原文档这句话方向对，但停在定性。补上数字（agent，单条 JD 均值）：

```
输入 14609 token = hit 10031 (68.7%) + miss 4578 (31.3%)

输入成本 = 10031 × 0.05  +  4578 × 1.5
         =      501      +     6868
             占量 68.7%      占量 31.3%
             占钱  6.8%      占钱 93.2%
```

**命中的 token 占了七成的量、不到 7% 的钱。**

这是"命中率是虚荣指标"最干净的实证——比原文档「概念 2」里预写的推断更硬，因为它是实测的。**预注册的预期被实测确认，这一条要在 report 里明确标出来。**

### 更反直觉的一条

| arm | hit 绝对量 | 命中率 | 总成本 |
|---|---|---|---|
| agent-baseline | **300928** | 0.687（最低） | **0.4020（最高）** |
| full-context | 63616 | 0.974（最高） | 0.0989 |

**agent 缓存命中的绝对量是 full-context 的 4.7 倍，成本却高 4.06 倍。缓存了更多，反而更贵。**

### 由此推出的可迁移规则

每加一轮，成本增量 = `0.05 × 历史长度(hit)` + `1.5 × 新增长度(miss)`。
miss 项主导的条件：`1.5N > 0.05H`，即 **N > H/30**。

实测（agent 单条 JD）：`H/30 = 334`，`N = 4578` → **超出 13.7 倍**。

> **多轮 agent 靠前缀缓存变便宜是个错觉。加一轮同时增加 hit 和 miss，而 miss 单价是 hit 的 30 倍——只要新增内容超过历史长度的 1/30，缓存就救不回来。而"新增"（工具结果 + assistant 调用）随轮数线性增长，是缓存的结构性盲区。**

这是 L10 唯一**普适**的机制性结论：与厂商无关、与本项目无关。

### A. 成本结构复算（验证本文第二、三节全部数字）

```python
# 无需调 LLM，直接用第八节表格的三列
PRICE = {"miss": 1.5, "hit": 0.05, "out": 4.5}   # 元/百万 tokens, off-peak
ARMS = {
    "workflow":       {"hit": 30592,  "miss": 1930,   "out": 17337},
    "full-context":   {"hit": 63616,  "miss": 1700,   "out": 20715},
    "agent-baseline": {"hit": 300928, "miss": 137351, "out": 40198},
}
for name, a in ARMS.items():
    c_in  = a["miss"] * PRICE["miss"] + a["hit"] * PRICE["hit"]
    c_out = a["out"] * PRICE["out"]
    tot   = c_in + c_out
    inp   = a["hit"] + a["miss"]
    ideal = inp * PRICE["hit"]                       # 输入 100% 命中的理想值
    print(f"{name:16s} 总成本={tot/1e6:.4f}元 "
          f"输入占比={c_in/tot:6.1%} 命中率={a['hit']/inp:.3f}")
    print(f"{'':16s} hit 占量={a['hit']/inp:6.1%} 占钱={a['hit']*PRICE['hit']/c_in:6.1%}")
    print(f"{'':16s} 完美缓存剩余上限={(c_in-ideal)/tot:6.1%}  单条={inp/30+a['out']/30:.0f}t")
fc = ARMS["full-context"]
base = (fc["miss"]*1.5 + fc["hit"]*0.05 + fc["out"]*4.5)
for name in ("workflow", "agent-baseline"):
    a = ARMS[name]
    print(f"{name} / full-context = "
          f"{(a['miss']*1.5+a['hit']*0.05+a['out']*4.5)/base:.2f}x")
```
