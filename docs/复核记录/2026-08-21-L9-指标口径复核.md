## 三、必须改（两条硬伤，会让 L9 结论站不住）

### ❌ 1. gaps precision/recall 口径错了：跨 JD 池化

**问题**：`eval/run.py:178-183` 里 `human_canon |= h; model_canon |= m`
——把 30 条 JD 的 gap **并成两个全局集合**再算交集。
这等于允许「模型在 jd-03 报的 gap，去匹配你在 jd-17 标的 gap」。

**实测两种口径的差距**：

| 口径 | workflow P / R | agent P / R |
|---|---|---|
| 池化（现行） | 0.790 / 0.961 | 0.814 / 0.941 |
| **逐 JD 微平均（正确）** | **0.447 / 0.659** | **0.467 / 0.721** |

关键数字：`|H| = 51, |M| = 62`——30 条 JD 一共才 51 个去重 canonical gap，
池化后集合太小，命中几乎是必然的。**0.94 是口径造出来的，不是模型能力。**

**更严重的是结论会反转**。`report.md` 第四节写「这是最反预期的一条——agent recall 反而低于 workflow」，
并据此下了 L9 主结论 ①。但按逐 JD 配对复算：

```
逐 JD recall 宏平均:  workflow = 0.652    agent = 0.691     ← agent 反而更高
配对比较:            agent 优 6 条 / 劣 8 条 / 平 16 条
Wilcoxon 符号秩检验:  p = 0.614                             ← 不显著
```

**正确的结论**不是「agent 反而更差」，而是
**「两组无统计差异，原先观察到的差异是池化口径的伪影」**。

**影响面**：
- `AGENTS.md` → 「gaps recall 0.94 + evidence 溯源 0.94 稳定可靠」需改写
- `AGENTS.md` → L9 硬结论 ①（工具化检索收益是边际的）、③ 需改写
- `eval/report.md` → 第三节「对比结论」、第四节需改写

> 附带一点：池化时 precision 的分母是全局 `|M|`，
> 所以第四节说的「precision 被虚高」原因**不止**别名落空，**口径本身就是主因**。

### ❌ 2. ρ 不可复现的归因错了：不是模型不确定，是统计量选错

> **已修正**：原稿曾质疑「代码里没有 seed」。经确认——seed 确实加过，
> 实测无效后删除。这属于**诚实的实验记录**，`AGENTS.md` 的表述成立，此点撤回。
> 唯一残留的小建议见下方「补充」。

**真正的原因**：Spearman 用错了场景。实测分布：

```
人工分:  60×17, 80×9, 40×3, 100×1    → 只有 4 个取值，57% 的样本全是 60
模型分(workflow):  60×14, 40×13, 20×3  → 只有 3 个取值
模型分(agent):     40×18, 60×11, 20×1  → 只有 3 个取值
```

30 个样本挤在 3~4 个档位上，**并列（tie）率超过一半**。
Spearman 在重度 tie 下方差极大——少数几条翻转就能让 ρ 从 0.06 蹦到 0.35。

**这不是模型不确定性，是指标选型错误**：给一个 5 档序数变量用了适合连续排序的统计量。

换成对档位友好的指标，数字立刻稳定且可解释：

| | workflow | agent |
|---|---|---|
| MAE | 19.3 | 20.0 |
| 完全一致率 | 0.30 | 0.20 |
| **±1 档（20 分）内** | **0.77** | **0.83** |

**「±1 档内命中 77~83%」是能写进简历的结论**，比「ρ=0.20 且不显著」强得多。

**建议**：主指标换 **Kendall's tau-b**（专门做 tie 校正）或**加权 Kappa（quadratic）**，
MAE / 档位一致率作辅助。Spearman 可以保留但降级为"已知在重 tie 下不适用"的对照。

**补充（小）**：seed 实验的过程建议在 `vault/` 或 `report.md` 里留一行记录
（"加过 seed=42，实测仍非确定，故移除"）。否则代码里看不到 seed，
`AGENTS.md` 的这句话就失去了可追溯的依据。

## 四、需要修正的设定（不改会被一句话问穿）

### ⚠️ 1. 对照实验缺了最该有的那一组：full-context

**实测 KB 规模**：

```
KB chunk 数:        17
KB 全文字符数:      3512   （≈ 2341 token）
top_k=5 覆盖了 KB:  29%
top_k=3 覆盖了 KB:  18%
agent 平均花费:     17896 token   ← 去检索一个 2341 token 的库
agent 迭代分布:     {2轮:18, 3轮:5, 4轮:5, 5轮:1, 6轮:1}
```

也就是说：**把 KB 整个塞进 prompt，比任何检索方案都更便宜、更准、零漏召。**
在这个规模下 agent 输给 workflow **不是实验发现，是算术必然**。

现在的结论「工具化检索收益是边际的」，面试官会问：
> *"你的知识库才 2000 token，为什么要检索？"*

必须有答案。**加一组 `full-context` arm**（不检索，KB 全灌），预期它在**所有指标上都赢**。
然后结论升级成真正有价值的那句：

> **「在 KB < 3k token 时检索是净负收益（实测 full-context 全面胜出）；
> 检索的价值要到 KB 超过 context 预算才出现。我用最小代价测出了这个拐点在哪边。」**

这比「工具化检索没带来收益」诚实得多，也高级得多。
**成本极低——单次调用 × 30，十几分钟。强烈建议在进 L10 之前补掉。**

### A. gaps 口径对比（池化 vs 逐 JD）

```python
import json, sys; sys.path.insert(0, '.')
from eval.run import load_dataset, load_aliases, canonical_gaps

rows = {r['jd_id']: r for r in load_dataset()}
am = load_aliases()
for arm in ['workflow', 'agent-baseline']:
    recs = [json.loads(l) for l in open(f'eval/raw_{arm}.jsonl', encoding='utf-8') if l.strip()]
    valid = [r for r in recs if r['error'] is None and r['model_result']]
    H = set(); M = set(); tp = fp = fn = 0
    for r in valid:
        h = canonical_gaps(rows[r['jd_id']]['human_gaps'], am)
        m = canonical_gaps(r['model_result']['gaps'], am)
        H |= h; M |= m
        tp += len(h & m); fp += len(m - h); fn += len(h - m)
    print(f'=== {arm} n={len(valid)}')
    print(f'  池化(现行) P={len(H&M)/len(M):.3f} R={len(H&M)/len(H):.3f} |H|={len(H)} |M|={len(M)}')
    print(f'  逐JD微平均 P={tp/(tp+fp):.3f} R={tp/(tp+fn):.3f} TP={tp} FP={fp} FN={fn}')
```

### B. 逐 JD 配对检验（结论反转的依据）

```python
import json, sys; sys.path.insert(0, '.')
from eval.run import load_dataset, load_aliases, canonical_gaps
from scipy import stats

rows = {r['jd_id']: r for r in load_dataset()}
am = load_aliases(); per = {}
for arm in ['workflow', 'agent-baseline']:
    recs = [json.loads(l) for l in open(f'eval/raw_{arm}.jsonl', encoding='utf-8') if l.strip()]
    per[arm] = {r['jd_id']: (lambda h, m: len(h & m) / len(h) if h else None)(
        canonical_gaps(rows[r['jd_id']]['human_gaps'], am),
        canonical_gaps(r['model_result']['gaps'], am))
        for r in recs if r['model_result']}
ids = [i for i in per['workflow'] if per['workflow'][i] is not None and per['agent-baseline'].get(i) is not None]
w = [per['workflow'][i] for i in ids]; a = [per['agent-baseline'][i] for i in ids]
print('宏平均 recall: workflow=%.3f agent=%.3f n=%d' % (sum(w)/len(w), sum(a)/len(a), len(ids)))
print('agent 优 %d / 劣 %d / 平 %d' % (sum(y>x for x,y in zip(w,a)), sum(y<x for x,y in zip(w,a)), sum(y==x for x,y in zip(w,a))))
print('Wilcoxon:', stats.wilcoxon(a, w))
```

import random, sys; sys.path.insert(0, '.')
from eval.run import load_chunks, evidence_containment, load_dataset
